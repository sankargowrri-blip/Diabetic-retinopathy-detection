# Diabetic Retinopathy Detection Using CNN (IDRiD)

An educational college mini project that fine-tunes ImageNet-pretrained
MobileNetV2 to classify retinal fundus images into five diabetic-retinopathy
grades and provides a Streamlit interface for trying a trained model.

> **Educational use only.** This project is not clinically validated and is not a
> medical device. Its output must not be used for diagnosis, treatment, or
> healthcare decisions. Results can be unreliable, especially with a small or
> imbalanced training set.

## Project contents

```text
app.py                      Streamlit application
train.py                    Dataset validation, CNN training, and test evaluation
requirements.txt             Pinned Python dependencies
packages.txt                 Streamlit Cloud system packages (none required)
dataset/idrid_labels.csv     Diagnosis labels (ensure attribution when sharing)
dataset/images/              Place local IDRiD images here, including subfolders
/archive/                     Local extracted source archive; ignored by Git
models/                       The real model is generated here after training
outputs/                     Test metrics, report, and plots generated by training
```

Training automatically creates `models/` and `outputs/` if needed. No fake model,
metrics, or graphs are included in this repository.

## Requirements

- Python 3.11 (64-bit)
- Windows, macOS, or Linux; CPU training is supported (a GPU is not required)
- IDRiD retinal images and their diagnosis labels

The pinned dependencies are selected for Python 3.11. TensorFlow can require
significant disk space and training time on CPU.

Open a terminal in the project folder and run:


## Add the dataset

Obtain the IDRiD dataset for research use from the
[IEEE DataPort IDRiD dataset page](https://ieee-dataport.org/open-access/indian-diabetic-retinopathy-image-dataset-idrid).
Review and follow the dataset provider's access and usage terms.

1. Use the IDRiD **Disease Grading training set** and its matching training
   labels. Keep the official testing set separate. In the supplied IDRiD
   archive, the training and testing partitions reuse image IDs, so mixing both
   partitions in the same image folder would make image-to-label matching
   ambiguous. This project makes its own stratified held-out split from the
   official training partition. Do not include the official testing partition in
   `dataset/images/`.
2. Put `idrid_labels.csv` at `dataset/idrid_labels.csv`.
3. Put the JPG, JPEG, and/or PNG retinal images anywhere below
   `dataset/images/`. Nested folders are searched recursively.
4. The CSV must contain `id_code` and `diagnosis` columns. The optional
   `Risk of macular edema` column is ignored for primary labels.
5. `id_code` must match an image filename without its extension. `diagnosis`
   must be an integer from 0 through 4:

   | Label | Grade |
   | --- | --- |
   | 0 | No Diabetic Retinopathy |
   | 1 | Mild |
   | 2 | Moderate |
   | 3 | Severe |
   | 4 | Proliferative Diabetic Retinopathy |

For a fresh copy of the project, the included CSV starts with only a header;
replace it with real label rows before training. In this workspace, the CSV and
images have been prepared from the official training partition. The dataset is
copyright by Prasanna Porwal, Samiksha Pachade, and Manesh Kokare, and is
provided under the Creative Commons Attribution 4.0 International license;
retain its attribution and follow its license terms.
Do not upload the full image dataset or the extracted `/archive/` folder to a
public GitHub repository. Training reports missing IDs, unlabelled images,
unreadable images, and the number of readable matched examples in each grade.
Invalid labels and ambiguous duplicate IDs stop training with an actionable
error rather than being guessed.

## Train and evaluate

With the virtual environment activated, run:

```powershell
python train.py
```

The defaults resize images to 224 × 224, use a batch size of 16, and train for
up to 12 total epochs: first a frozen ImageNet-pretrained MobileNetV2 backbone,
then fine-tune its last layers at a low learning rate. Training uses mild
horizontal-flip, rotation, and zoom augmentation only on training batches;
inputs are scaled to [0, 1], then a model layer rescales them to [-1, 1] for
MobileNetV2. Reduce resource use or training time with:

```powershell
python train.py --image-size 160 --batch-size 8 --epochs 8
```

Other options include `--csv`, `--images-dir`, and `--seed`. `--epochs` must be
between 1 and 20. Class weights are calculated from training labels only.
Stratified training, validation, and held-out test splits are checked for
overlap. Early stopping, validation-loss learning-rate reduction, and
validation-only checkpoints are used. The original CNN is preserved as
`models/dr_model_cnn_baseline.keras`; its predictions and the final transfer
model are compared on the same held-out test indices. The test split is not
used for model selection. ImageNet weights may need to download on the first
run.

Training creates:

- `models/dr_model.keras` — the trained MobileNetV2 checkpoint
- `models/dr_model_cnn_baseline.keras` — preserved original CNN for comparison
- `outputs/metrics.json` — held-out test accuracy, macro precision, macro recall,
  macro F1, and test-set size
- `outputs/classification_report.txt` — per-grade classification report
- `outputs/baseline_classification_report.txt` — original CNN's report on the same test split
- `outputs/model_comparison.json` — same-split baseline and transfer-learning metrics and test indices
- `outputs/baseline_confusion_matrix.png` — original CNN confusion matrix on the same test split
- `outputs/confusion_matrix.png`
- `outputs/accuracy.png` and `outputs/loss.png`

The IDRiD grading training partition has only 413 images and is imbalanced (in
this copy, the five grades have 134, 20, 136, 74, and 49 examples). Results from
one 83-image held-out split have substantial uncertainty and do not establish
clinical generalization. Transfer learning does not guarantee better results.
Do not tune repeatedly against the test set; use additional independent data for
reliable comparisons.

## Run the Streamlit app locally

After training a model:

```powershell
python -m streamlit run app.py
```

The app runs independently of the dataset and training script; it needs only the
trained model to make predictions. Upload a JPG, JPEG, or PNG and click
**Analyze image** to see the five grade probabilities. Image decoding, resizing,
and [0, 1] input scaling match the training pipeline; the model includes the
MobileNetV2 rescaling layer. If there is no model, the app explains what is
missing instead of showing sample predictions.

The app uses the high-contrast light theme in `.streamlit/config.toml`. Home,
Prediction, About Project, and Model Performance are available in the sidebar.
The performance page reads actual saved metrics, model comparisons, reports,
and plots from `outputs/`; missing files are reported rather than replaced with
sample results.

## Push to GitHub

Create an **empty** GitHub repository (do not initialize it with a README or
license). From PowerShell in this project folder, initialize Git if needed and
check the files selected for upload:

```powershell
git init
git status --short
git add -A
git status --short
```

Before committing, confirm the staged changes do **not** include `archive/`,
image files under `dataset/images/`, `.venv/`, or `.streamlit/secrets.toml`.
The `.gitignore` excludes these. It is expected to include the small diagnosis
CSV, application files, `.streamlit/config.toml`, trained model files, and
evaluation reports/plots. The IDRiD dataset images must not be uploaded.

Then commit and connect your empty GitHub repository (replace the URL with the
one shown on GitHub):

```powershell
git commit -m "Prepare diabetic retinopathy Streamlit project"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

The trained `models/dr_model.keras` is approximately 24 MB in this workspace,
under GitHub's 100 MB per-file limit. The baseline model and evaluation
artifacts are small enough to include as well. If a future model exceeds 100
MB, use Git LFS or external model hosting. For external hosting, configure the
Streamlit app secret `DR_MODEL_URL` with a direct HTTPS download URL; the app
downloads the model once when there is no local model file. Never put access
tokens in source code.

## Deploy on Streamlit Community Cloud

1. Push the project code, trained model, theme, and evaluation outputs to GitHub
   using the steps above. Do not upload the full image dataset or `archive/`.
2. Sign in to [Streamlit Community Cloud](https://share.streamlit.io/).
3. Choose **Create app** and select your GitHub repository and the `main` branch.
4. Set the main file path to `app.py`.
5. Choose Python 3.11 in the app settings if prompted; dependencies are listed
   in `requirements.txt`, and the visual theme is in `.streamlit/config.toml`.
6. If using externally hosted model storage, add `DR_MODEL_URL` in the app's
   **Settings → Secrets** as a TOML string:

   ```toml
   DR_MODEL_URL = "https://example.com/direct-download/dr_model.keras"
   ```

7. Deploy and test the public URL with a supported fundus image. Check both
   **Prediction** and **Model Performance** after deployment.

The cloud app does not need the dataset and does not run training. Free hosting
has CPU, memory, storage, and resource limits; TensorFlow and a large model may
approach those limits. The project does not promise that every model size will
fit the free service. Streamlit Community Cloud is the recommended deployment
for this Streamlit project. Vercel and Netlify primarily host web front ends;
they would need a separate Python inference backend and are not a direct
replacement for Streamlit Community Cloud here.
